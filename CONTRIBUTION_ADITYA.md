# Aditya's Contributions

| Branch | Description | Stage |
| --- | --- | --- |
| `feature/S2-XGBoost` | Built `XGBoostForecaster` (`src/drift_lab/forecasting/xgboost_forecaster.py`) on the frozen `Forecaster` contract. It uses lag features (a contiguous range up to 48 half-hours, plus 2-day, 3-day and weekly lags) and calendar features (hour, minute, day of week, month). `fit` uses the training window only. `predict` forecasts one row at a time, recursively, and takes observed lags where they exist, so the model can be fitted once and rolled through the test stream without leakage. Early stopping uses a chronological validation slice taken from the end of the training window. Added tests in `tests/test_xgboost_forecaster.py` and generated the baseline forecast CSVs. | Forecasting |
| `docs/s2-research-gradient-boosting` | Added the research notebook `notebooks/research/gradient_boosting.ipynb`. It explains what XGBoost is, its architecture and how it works, and how it connects to the four adaptation arms. It references two research papers, and it walks through the lag and calendar features with worked examples. Also documented `fit`, `predict()` and `observe()` in the forecaster. | Forecasting |
| `test/s3-xgboost` | Hyperparameter tuning of `XGBoostForecaster` in `src/drift_lab/forecasting/xgboost_forecaster.py`. The tunable settings are exposed as constructor parameters: `n_estimators`, `max_depth`, `learning_rate`, `max_lag`, `extra_lags`, `early_stopping_rounds` and `validation_fraction`. `subsample` and `colsample_bytree` are set to 0.8 in `fit`. Early stopping uses a chronological validation slice taken from the end of the training window, so the number of boosting rounds is chosen without touching calibration or test data. The settings are kept as public attributes so they appear in each run's `config_hash`. The adaptation experiments build the model with these settings (`run_aemo_adaptation_arms.py`). | XGBoost tuning |
| `feature/s3-evaluation-metrics` | Built the detection-evaluation layer in `src/drift_lab/evaluation/evaluation.py`, with tests in `tests/test_evaluation.py`. Added `match_unmatch`, which debounces detections and matches them one-to-one to documented AEMO events, Tier 1 before Tier 2, and reports unmatched detections as "Unmatch" rather than false alarms. Added regime assignment (pre-drift / drift / post-drift, where an unmatched detection counts as pre-drift) and the synthetic-detection metrics (detection delay, false alarms per 10,000, missed detections). Later commits added tier support and changed the output format. | Table 1 & 2 |
| `feature/s4-t3-t4-evaluation-metrics` | Added the forecast-quality metrics in `src/drift_lab/evaluation/evaluation.py` that Tables 3 & 4 use: absolute error and MAE by regime (`calculate_forecast_metrics_by_regime`), adaptation gain against Arm A per retrain (`calculate_adaptation_gain`) and pinball loss (`calculate_pinball_loss`). | Table 3 & 4 |
| `feature/s5-split-conformal` | Implemented split conformal prediction intervals. Main has this logic as `FixedSplitConformal` in `src/drift_lab/uncertainty/fixed_split_conformal.py`, with helpers in `conformal_common.py`. The radius is the finite-sample conformal quantile (rank ceil((n+1)·coverage)) of absolute calibration residuals, set once at calibration, with bounds `forecast ± radius`. It returns an infinite radius if there are too few scores, and flags escalation when the interval width exceeds a threshold. Added the UQ metrics in `evaluation.py`: empirical coverage, mean and normalised interval width, rolling and worst-24h coverage, and `calculate_uq_metrics_by_regime`. Built the Table 5 script (`experiments/produce/uncertainty/produce_table_t5.py`), which reports coverage and width by regime as mean ± sd across seeds. Unit tests are in `tests/test_conformal_uq.py`. | Table 5 |
